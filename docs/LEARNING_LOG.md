# 学习记录：从环境配置到前后端联调

这份记录用于说明本项目的学习过程与验证证据。项目采用 AI 辅助开发；记录会区分已经亲自操作和能够解释的内容，以及仍需继续独立练习的部分。

## 1. 起点与目标

项目以一份**经授权公开使用的匿名集训示例代码**为起点。起始版本已经包含：

- 一个 Vue 3 + Vite 前端；
- 一个 Spring Boot 后端；
- `GET /api/decision/random` 随机决策接口；
- 单一“美食”类别和基础页面样式。

本次练习的目标不是从空白独立完成全部代码，而是在能够运行和理解起始项目的基础上，完成环境联调、功能扩展、交互优化和验证。

## 2. 环境配置与基础联调

在正式修改作业前，先完成并验证了以下工具链：

| 工具 | 验证版本或用途 |
|---|---|
| Java | Temurin JDK 17 |
| Maven | 3.9.16，管理后端依赖、测试和运行 |

通过一个最小联调示例验证了完整链路：

```text
Vue 页面（localhost:5173）
→ Axios 发送 HTTP 请求
→ Spring Boot 接口（localhost:8080）
→ 返回字符串或 JSON
→ Vue 更新响应式数据和页面
```

这一阶段亲自完成并验证了：

- `java --version`、`mvn --version`、`node --version` 和 `npm --version`；
- Maven 与 JDK 17 的关联；
- 前后端分别启动与停止；
- 直接访问后端接口；
- Axios 获取后端响应并更新 Vue 页面；
- 后端停止时前端能够显示错误状态。

## 3. 对起始项目的理解

阅读和运行起始代码后，确认了三个关键位置：

- `App.vue`：页面结构、响应式状态、按钮事件和结果渲染；
- `vite.config.js`：把前端的 `/api` 请求代理到 `localhost:8080`；
- `CardController.java`：接收 GET 请求、根据 `type` 筛选候选项并随机返回记录。

实际项目采用的响应结构为：

```json
{
  "type": "娱乐",
  "name": "散步听歌",
  "description": "戴上耳机走一走，让大脑暂时放空。"
}
```

学习资料中出现过 `{ code, data, msg }` 形式的通用接口模板，但本项目没有机械套用模板，而是以实际前后端代码已经共同使用的接口合同为准。

## 8. 回顾这次实践

> 以下感悟于 2026 年 10 月回顾暑期经历时整理，并经本人确认。

回看这次暑期集训，这是我在编程基础还比较有限时，借助示例和AI指导，走过的一次较完整的Web项目实践。

开始时，我还没有系统学习Vue和Spring Boot，很多开发工具和操作也不熟悉。我希望完成集训任务、为加入协会做准备，同时尽量弄明白每一步在做什么。所以在配置环境和运行项目时，我要求AI一步一步指导，自己操作后再反馈结果，遇到不理解的地方继续追问。

这次实践让我对前后端如何配合有了具体认识：页面上的按钮通过Axios发送请求，经过Vite代理到后端，Controller处理后返回JSON，Vue再把结果显示出来。这些概念不再只是笔记里的名词，而是能和自己运行过的页面、接口及代码位置对应起来。

在改造示例时，我把功能范围确定为美食和娱乐两类，并参与了运行检查和交互调整。反复操作页面后，我发现“再来一次”会引起闪烁，也提出了保留页面主体、让结果平滑变化的要求。回头看，这部分经历让我开始注意到：功能能运行之后，还需要看实际使用是否自然、是否有让人不舒服的细节。

AI承担了不少代码实现、排错和文档整理工作，我是在指导下完成这次实践的。项目完成并不代表我已经能够独立开发同类网站，但它给了我一个具体参照，让我知道自己接触过什么、理解了什么，以及哪些基础还需要继续学习。

最后，我录制了演示视频，获得了学姐的肯定，也把项目上传到GitHub作为学习记录。我希望保留的不只是最终页面，还有从环境配置、运行示例到提出修改、检查结果和发布项目的过程。
